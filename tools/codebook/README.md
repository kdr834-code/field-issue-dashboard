# 에러코드 모음집 갱신 도구

모델별 화면설계서(`.pptx`)를 읽어 `error_codes.json`을 갱신합니다.

Z 드라이브 위치: `Z:\품질보증실\공용\품질개선팀\17. 모델별 에러코드\<모델>\`

## 왜 도구가 필요한가

설계서를 눈으로 옮겨 적으면 **반드시 빠집니다.** 실제로 그랬습니다.

- 설계서는 한 코드가 여러 슬라이드에 나뉘어 있습니다 (구형/신형, Main/HP/RF)
- **팝업 화면이 그림으로 들어 있어** 글자만 읽으면 코드 자체를 놓칩니다
- **슬라이드 머리글과 팝업에 찍힌 코드가 다른 장이 있습니다**

DENSITY에서 머리글만 읽었을 때 `N-103`이 통째로 빠졌습니다. 실제 접수 건에
16번이나 나오는 코드였고, 대시보드에서 계속 "모음집에 없는 코드"로 떴습니다.

## 쓰는 순서

```bash
# 1) 설계서에서 글자와 그림을 뽑습니다
node tools/codebook/extract-pptx.js "Z:/.../DENSITY 통합 화면설계서....pptx" work-density

# 2) 그림을 OCR로 읽습니다 (윈도우 내장 OCR, 별도 설치 불필요)
powershell -ExecutionPolicy Bypass -File tools/codebook/ocr-images.ps1 work-density

# 3) 합쳐서 결과만 확인합니다 (파일은 바꾸지 않습니다)
node tools/codebook/build-entries.js work-density

# 4) 확인이 끝나면 반영합니다
node tools/codebook/build-entries.js work-density --apply "DENSITY"
```

`--apply`의 모델명은 `error_codes.json`의 `model` 값과 **정확히** 같아야 합니다.
현재 값: DENSITY, DENSITY Noir, LINEARZ, Cellec, AQUAcel, POTENZA, TRI-BEAM,
Edge One, ULTRA LIFT, ULTRAcel Q+, INTRAcel PRO, INTRAgen, AcGen

## 3단계에서 반드시 눈으로 볼 것

```
[머리글과 팝업 코드가 다른 슬라이드] 5장
  89번: 머리글 E-201 / 팝업 N-201
  102번: 머리글 N-21 / 팝업 N-103      ← 머리글이 오기인 경우
```

도구는 두 경우를 이렇게 나눕니다.

| 상황 | 처리 |
|---|---|
| 머리글 코드가 설계서 어디에서도 팝업에 안 나옴 | 옛 표기로 보고 **두 코드에 같은 내용**을 답니다 |
| 머리글 코드가 다른 슬라이드에서 제 팝업을 가짐 | 이 장의 머리글이 틀린 것으로 보고 **팝업 코드만** 씁니다 |

자동 판단이므로 **결과를 사람이 확인해야 합니다.** 이상하면 설계서 해당 쪽을 직접 여세요.

```
[메시지 목록 밖에서 발견된 코드] N-260
```

설계서 앞쪽 동작 설명 화면에 찍힌 코드입니다. 자동으로 넣지 않으니 필요하면 직접 추가하세요.

## 알아둘 점

- **`en`(원문) 칸은 OCR 결과**라 오독이 남아 있을 수 있습니다. (`pressu re` 같은 띄어쓰기)
  뜻을 알아보는 데는 지장이 없지만 그대로 인용하지는 마세요.
- 설계서 쪽이 비어 있으면 **기존 값을 지우지 않습니다.** 그림으로만 있는 칸이 있기 때문입니다.
- 설계서에 없는 기존 코드도 지우지 않고 뒤에 남깁니다.
- 같은 작업폴더로 다시 돌려도 결과가 같습니다. 안심하고 재실행하세요.

## 걸렸던 함정

- `ocr-images.ps1`은 **BOM 붙은 UTF-8**이어야 합니다. 없으면 PowerShell 5.1이
  ANSI로 읽어 한글 주석에서 구문 오류가 납니다.
- 설계서 그림은 **90도 돌아간 채** 저장돼 있습니다. 그대로 OCR하면 글자가 하나도 안 잡힙니다.
- `unzip`에 `ppt/slides/*`만 주면 `_rels`가 안 딸려와 그림 연결 정보를 통째로 잃습니다.
