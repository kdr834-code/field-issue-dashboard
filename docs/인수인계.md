## 한 줄 요약

SharePoint 리스트의 필드 불량 데이터를 조회·분석하는 단일 HTML 대시보드.
Netlify에 배포돼 운영 중이며, 화면 8개가 동작합니다.

| 상세 데이터 | 운영 중 | 조회·필터·검색 / **수정 저장 경로는 미검증** |

## 반드시 확인해야 할 미검증 항목

우선순위 순입니다. **제가 사용자 계정으로 로그인할 수 없어 확인하지 못한 것들입니다.**

### 1. 편집 저장이 실제로 SharePoint에 반영되는가 (위험도 높음)

상세 데이터에서 항목을 수정하면 Graph API로 SharePoint에 씁니다.
**단 한 번도 실제 계정으로 검증된 적이 없습니다.**

가장 위험한 부분은 **`분석 담당자` 사람(Person) 필드**입니다.
이름이 아니라 내부 LookupId로 저장해야 하는데, 추가 권한 없이 쓰려고
이미 목록에 등장한 사람들만 후보로 모아 씁니다(`buildPeopleDirectory`).
목록에 없는 사람을 지정하려 하면 실패할 수 있습니다.

**검증 방법** — CLOSE 상태인 건 하나를 골라 `분석 처리결과`만 고쳐 저장한 뒤,
SharePoint 원본 화면에서 반영됐는지 확인.

### 2. Master Version 저장/불러오기 (위험도 중간)

릴리즈 PDF를 올리면 사이트 문서 라이브러리의 `MasterVersion` 폴더에 저장하고,
모든 사용자가 같은 내용을 봅니다. **저장 경로가 검증되지 않았습니다.**

**검증 방법** — PDF를 올린 뒤 ① "반영 완료" 표시가 뜨는지 ② 문서 라이브러리에
`MasterVersion` 폴더가 생기는지 ③ 다른 PC에서 같은 내용이 보이는지.

`403`이 나면 문서 라이브러리 쓰기 권한 문제입니다.
(새 Azure 권한은 필요 없습니다. `Sites.ReadWrite.All`이 문서 드라이브까지 포함합니다)

### 3. Azure 앱 등록의 소유자 확인

클라이언트 ID `79c4da92-...` 의 소유자가 누구인지 확인해야 합니다.

- 본인 또는 팀이 소유자 → **리디렉션 URI 추가를 직접 할 수 있음.** 호스팅 이전이 자유로워집니다
- IT가 소유자 → 주소가 바뀔 때마다 요청 필요

확인 경로: Azure Portal → Microsoft Entra ID → 앱 등록 → 소유자 / 인증(Authentication)

API 권한은 이미 관리자 동의가 끝나 다시 받을 필요가 없습니다.
리디렉션 URI 추가는 권한 동의와 별개 설정입니다.

### 4. `error_codes.json` 공개 노출 판단

13개 모델 463건의 서비스 매뉴얼 에러코드입니다.
Netlify에 올라가 있어 **주소만 알면 누구나 내려받을 수 있고**,
GitHub 저장소도 Public이라 검색에 노출됩니다.

사용자가 Public 공개를 선택한 상태입니다. 회사 기준상 문제가 없는지는 확인되지 않았습니다.

## 다음에 할 만한 것

사용자가 관심을 보였으나 아직 만들지 않은 것들입니다.

- **파레토 차트** — 대시보드 실데이터 기준. 20%의 원인이 80%를 차지하는지
- **FMEA / RPN 계산** — 품질 도구에 추가
- **미입력 채우기 필터** — Lv.2가 비어 있는 건만 모아 보여주기
- **Master Version 제개정 이력** — PDF의 이력 시트도 표시

## 하지 않기로 한 것 (다시 제안하지 마세요)

이유는 `docs/결정기록.md`에 있습니다.

- 엑셀·PPT 추출 기능 — 품질이 기대에 못 미쳐 사용자가 취소
- Supabase 등 다른 로그인으로 교체 — 데이터 조회가 끊깁니다
- Supabase로 호스팅 이전 — 정적 호스팅 제품이 아닙니다
- 장기 미처리 건수 지표 — 오해를 부르는 숫자라 넣지 않기로 함

1. 주간 분석 7주로 축소, 현황 분석 발생기간 기본값 3개월이내
